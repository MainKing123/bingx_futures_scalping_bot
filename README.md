# MEXC · VOLIUM

Python-бот для пяти ликвидных USDT-фьючерсов MEXC. Экспериментальная V6 учитывает [первое видео TRADING VOLIUM](https://www.youtube.com/watch?v=jYvt1hSTPxc) и [разбор от А до Я](https://www.youtube.com/watch?v=bL4z-AjkNY0): текущий D1 A→B и согласованный поток H1 → снятие ликвидности → поглощение или инверсия FVG → восстановление трети полного движения M5 → лимитный ретест, структурные SL/TP и gross 2R.

По умолчанию работает **экспериментальная V6 paper trading** на публичных данных, без ключей и реальных ордеров. V6 разрешает только intraday D1/H1/M5 и отклоняет live при загрузке настроек. Замороженные V1–V5 сохранены для воспроизводимости; исторические контрольные команды ниже используют прежнюю V1. Scalp остаётся отдельной старой гипотезой V5, swing — профилем `v1_guarded`.

Плечо 10–50 выбирается по активу и ограничениям контракта: BTC/ETH до50, SOL/XRP до25, остальные до10. Плановый риск до0,5% капитала включает комиссии и проскальзывание. Плечо уменьшает маржу при одинаковом риске; PnL счёта и доходность на маржу показаны отдельно. Слишком тесный либо широкий структурный стоп отклоняет идею. [Финансовая модель](docs/execution_economics.md).

## Запуск на Windows

Проверенная версия Python — 3.12. Выполните в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m app
```

Откройте [панель бота](http://127.0.0.1:8000/dashboard) или [документацию API](http://127.0.0.1:8000/docs). Остановка — Ctrl+C. SQLite-журнал `volium.db` хранит сигналы, заполнение бумажных заявок и состояния реальных ордеров; восстановление после перезапуска не создаёт повторную заявку по той же идее.

## Какие пять пар торгуются

`PAIR_SELECTION=dynamic`: BTC и ETH входят обязательно, если проходят проверки, ещё три пары выбираются по волатильности. Все пять должны входить в топ-20 по капитализации CoinGecko, кроме стейблкоинов и производных; иметь доступный для API линейный USDT-контракт MEXC и оборот за 24 часа от 50 млн USD. Кандидаты ранжируются по среднему нормализованному true range за 96 закрытых M15-свечей. Отбор обновляется каждый час; панель показывает капитализацию, оборот и волатильность.

Новая V5 robustness проверяет BTC, ETH, ZEC, SOL, DOGE на ранее известном снимке; старый V1 снимок содержал ZEC, SOL, DOGE, XRP, ETH. Такой ретроспективный отбор не является независимым доказательством. Текущий состав меняется вместе с рынком. Если проверенный список либо обязательный BTC/ETH получить невозможно, новые сигналы приостанавливаются. `PAIR_SELECTION=fixed` позволяет явно закрепить пять символов из `TRADING_SYMBOLS`. Политика источников описана в [docs/universe.md](docs/universe.md); правило core дополнительно задаёт `app/runtime_settings.py`.

## Правила и выбранные трактовки

Новая [спецификация V6](docs/strategy_v6.md) отделяет требования источника от численных прокси. `VOLIUM_STRATEGY_PROFILE=v6_current_leg` — текущий бумажный профиль. A определяется снятием и реакцией без обязательного pre-A HH/HL или будущего правого фрактала; старую идею прекращают при нарушении A или достижении B. Восстановление M5 считают от отдельного начала манипуляции, цель H1 в его знаменатель не подставляют. Вход для gross 2R: `(target + 2 * stop) / 3`; TTL30минут. После округления проверяется net reward/risk с издержками.

Последний подтверждённый живой M5 пик/впадина как начало движения, HTF реакция через engulfment/FVG, pivot width2, контекст80 и ожидание12баров — фиксированные инженерные допущения. Известный пример BTC24июня2025 помогает проверить контекст, но не является независимым тестом прибыли или доказательством точного входа автора. Полное совпадение с ручной разметкой не доказано. [Прежняя V5](docs/strategy_v5.md), [замороженная V1](docs/strategy.md).

Основные сессии: 10:00–12:00 и 16:30–18:00 UTC+3. Конец второго окна — обоснованное допущение: видео указывает только 16:30. Те же криптовалютные окна применены к выбранным пяти парам. В исторической проверке V1 отдельно сравнивались утреннее окно и гипотеза привязки к местному времени Лондона/Нью-Йорка с DST; фиксированная V5 таких вариантов не добавляет. [Индикатор автора](https://www.tradingview.com/script/1WFDkBkJ-Trading-Sessions-by-klmn1k-from-Trading-Volium/) защищён: точные настройки криптовалютных сессий публично не раскрыты; исследование — в [docs/sessions.md](docs/sessions.md).

## Риск и реальное исполнение

Стандартные ограничения текущей V6: плановый риск до0,5% капитала вместе с комиссией и проскальзыванием, максимум три активные идеи, дневной порог убытка2% капитала на начало дня UTC и плечо10–50 по активу. Бумажный журнал списывает стоимость входа сразу при заполнении, стоимость выхода — по фактическому выходному номиналу, начисляет публичный funding один раз и сохраняет движения денег атомарно. Маржа и стоимость входа резервируются из общего счёта; пропущенные данные funding или оценки открытых позиций приостанавливают новые входы. После перезапуска журнал восстанавливает баланс и UTC-дневной результат без повторных начислений. [Бумажный счёт и его ограничения](docs/paper_cash.md).

Только M1-свечи, полностью начавшиеся после фактической постановки бумажной заявки, могут её заполнить. Гэп, funding и ликвидация могут привести к убытку больше планового; точная ликвидация по fair price и очередность исполнения внутри свечи не восстанавливаются. Защита по ликвидационной дистанции является консервативной проверкой допуска с текущими публичными параметрами контракта.

Адаптер реальных ордеров поддерживает лимитный вход с приложенными SL/TP, округление контрактного количества и цен, уникальный `externalOid`, отмену остатка частичного заполнения и сверку по бирже. После таймаута отправки ордер повторно вслепую не посылается. Неопределённое исполнение или отсутствие подтверждённой защиты приостанавливает входы. API не позволяет включить live через панель.

Профили `v6_current_leg`, `v5_equal` и `v5_strict` отклоняют `AUTO_EXECUTION=true`. Сохранённый адаптер live доступен только прежнему `v1_guarded`, для него нужны локальные `MEXC_API_KEY`, `MEXC_API_SECRET` и явное включение в `.env`. В рамках разработки реальные ордера не отправлялись; адаптер проверен на тестовых ответах API. Исторический бэктест не подтверждает готовность исполнения на конкретном аккаунте и не включает live автоматически.

В live дневной капитал оценивается по текущему капиталу биржи минус известный дневной реализованный результат бота. На новом UTC-дне берётся первое наблюдение капитала. Внешние сделки, ввод/вывод и плавающий PnL делают эту оценку отличной от точного капитала в полночь; источник оценки виден в `/api/status`. Нулевой или некорректный капитал блокирует входы.

Если сверка live-закрытия не возвращает однозначное время исполнения, журнал использует время подтверждения закрытия; результат после длительного отключения может попасть в другой UTC-день. Paper trading сохраняет время исторической свечи закрытия и корректно восстанавливает дневной результат через полночь.

## Фиксированное исследование V6

[План V6](docs/research_v6_protocol.md) содержит28сравнений: одна V6 и замороженная V5 equal, intraday, одинаковые baseline/stress costs и общий финансовый движок V5. MEXC исходные5пар на177днях (90/45/42), известные Binance BTC/ETH2024–2025 и отдельно ранее не использованный2021год. Все результаты, включая нули и убытки, публикуются без выбора победителя по final. Это726stage trials с предыдущими698; отдельно2старых shared-wallet replay. [Полный итог V6](docs/strategy_v6_report.md), [компактный индекс всех28](docs/strategy_v6_evidence.json).

2021 выбран календарно до скачивания/результатов, использует настоящие M1 и funding из72официальных архивов с CHECKSUM; Binance результаты не являются MEXC доходностью. Известные окна и ретроспективная корзина независимым holdout не называются. V6 правила после PnL не меняются.

CLI `python -m app.external_data_v6` скачивает отдельный2021кэш, `python -m app.research_v6 --help` показывает регистрацию/этапы. Регистрация требует полную поставку прежних планов/результатов и source review в outputs, сохранённую V5 и публичные финансовые снимки. Планы привязаны к абсолютным путям и byte hashes: при переносе рабочей папки необходима новая регистрация с раскрытием переиспользованных результатов; старая подпись не переносится молча. Последовательно register → train → validation → final → external. Завершённые группы нельзя повторно запускать как новые попытки поиска.

## Фиксированное исследование V5

Новая [проверка V5](docs/research_v5_protocol.md) заранее фиксирует три модели и57расчётов, включая нулевые и отрицательные исходы. MEXC BTC/ETH:150дней train,90 validation,90 final из всей330-дневной истории. Binance BTC/ETH:2024 train, первая половина2025 validation, вторая половина final, отдельно intraday/scalp с настоящими M1. Из57проверок12описывают известные последние30дней общего счёта пяти пар MEXC, остальные45 — основной BTC/ETH. Baseline издержки на сторону5bps комиссия+2bps slippage; stress10+5bps. Funding каждой площадки учтён отдельно. Состояние счёта сбрасывается к1000USDT для каждого fold; результаты folds не выдают за одну непрерывную кривую.

`python -m app.research_v5 draft` показывает фиксированный дизайн без вычисления сигналов или доходности. Перед расчётами `register` требует оба peer-плана, шесть прежних завершённых планов V2–V4, исходный архив V4 с manifest, source review и публичные контрактные snapshot. Далее выполняются `train`, `validation`, `final` и отдельно MEXC `robustness`. Все три модели проходят final один раз даже при нуле обучающих сигналов; выбора победителя по final нет. Подробные аргументы приведены в CLI `--help` и протоколе.

Текущие MEXC ограничения контракта и Binance maintenance margin1% — явно исторически неизвестные прокси. M5 MEXC не заменяет минутные исполнения; ликвидации по исторической fair price не реконструируются. Повторно использованные данные и выбор BTC/ETH после прежних результатов раскрыты. Положительный результат на нескольких сделках не означает готовность к live.

После основных57отдельно зарегистрированы6описательных проверок того же состава BTC/ETH/ZEC/SOL/DOGE на177днях общих M5. Правила и параметры сохранены; начало механически сдвинуто для прогрева990свечей. Это расширение после известных основных исходов, без независимого holdout и вне eligibility. Всего63новых расчёта,698с учётом прежних635; два старых общих портфеля учитываются отдельно. Связанные strict/equal и перекрывающиеся окна не увеличивают независимую выборку.

**Прибыльное преимущество не подтверждено.** V5 на330днях BTC/ETH MEXC дала одну train-сделку +7,78USDT, затем ноль закрытых validation/final. В пяти парах месячный scalp дал две сделки +2,10USDT, а177-дневный intraday — три сделки −2,79USDT; в соответствующих stress случаях новых сделок нет. Эти отдельные счета начинаются с1000USDT, их результаты не складываются. Ни одна модель не прошла фиксированные критерии. ## Исторический комплексный бэктест V1

Бэктест использует публичные MEXC OHLC и реальные исторические ставки funding, ключи не нужны. Каждый символ получает независимый счёт 1,000 USDT; результаты по символам нельзя складывать как результат общего портфеля. Сегодняшние пять пар закрепляются на весь исторический период: это **смещение текущего состава**, а не восстановленный ежедневный исторический рейтинг.

Для воспроизведения полного исследования с явным составом:

```powershell
.\.venv\Scripts\python.exe -m app.backtest_suite --symbol ZEC_USDT --symbol SOL_USDT --symbol DOGE_USDT --symbol XRP_USDT --symbol ETH_USDT --workers 3 --out-dir outputs
```

Первый запуск загружает и замораживает данные в `.cache/suite`, следующие воспроизводят снимок. `--cache-only` запрещает сеть; `--refresh-cache` создаёт новый снимок. `--dry-run` печатает план без загрузки. Можно передать `--universe-json outputs/universe_selection.json` для состава из сохранённого отбора или повторяемый `--scenario` для отдельных сценариев.

Полный план содержит 255 прогонов: пять пар × 51 сценарий. Внутридневной режим — до 180 дней, скальпинг — до 30, свинг — до 365. Есть непересекающиеся временные участки, длинные/короткие позиции, стресс стоимости, чувствительность численных трактовок, сессии и сравнение с более мелким M1-исполнением. Перекрывающиеся сценарии не увеличивают независимую выборку. Ослабление обязательного дневного снятия помечено как отклонение от концепции, а не предложенная замена стратегии.

При неоднозначном порядке касаний стоп имеет приоритет; выгодный тейк на неизвестном порядке внутри свечи входа не засчитывается. Незакрытые позиции, незаполненные/истёкшие заявки и реализованная/маркированная просадка выводятся отдельно. Funding оценивает стоимость позиции по последнему известному закрытию свечи, а не исторической fair price. Модель не включает очередь ордеров, ликвидацию или фактические частичные заполнения. Итоговые `report.md`, `backtest_summary.csv`, `backtest_suite.json` и контрольные суммы исходных данных сохраняются в выбранную папку результатов.

Быстрый диагностический replay: `python -m app.replay --mode intraday --days 30 --out outputs/replay.json`. Без `--symbol` он выбирает текущие пять пар; для заданных символов параметр повторяется. Полный исследовательский результат создаётся комплексным runner выше.

Дополнительно реализован **общий счёт пяти пар** на последних 30 днях с M1-исполнением: лимитные заявки и позиции делят капитал, маржу, три места и дневной лимит. Каждый режим тестируется отдельно. Выходы и funding всех пар обрабатываются перед новыми заявками на той же минуте; одновременные сигналы получают приоритет в зафиксированном порядке списка. Неполная M1-история прерывает расчёт. Запуск на сохранённом снимке:

```powershell
.\.venv\Scripts\python.exe -m app.portfolio_replay --cache .cache/suite --selection outputs/universe_selection.json --out-dir outputs
```

Портфельный результат: intraday — 3 сделки, 979.63 USDT из 1,000; scalp — 7 сделок, 981.10 USDT. Прибыльность автоматизированной версии не подтверждена. В 20 основных индивидуальных экспериментах из полного набора только один имеет положительный результат, пять — отрицательный, 14 — без закрытых сделок. Свинговые варианты не дали закрытых сделок на годовом окне. Число сделок слишком мало для надёжной оценки. Подробности: [комплексный отчёт](docs/backtest_report.md), [общий счёт](docs/portfolio_report.md), [времена и контрольные суммы данных](docs/backtest_evidence.json).

Первичная поставка v1 сохранена как `mexc_volium_bot_v1.zip`. Для точного офлайн-повтора v1 распакуйте отдельный `public_data_snapshot.zip` в `.cache/suite`, затем запустите комплексный runner с `--cache-only --universe-json outputs/universe_selection.json`. Архив содержит только публичные OHLC, funding и снимок отбора. Оригинальный индекс v1 сохранён как `manifest_v1_original.json`; актуальный индекс всей поставки — `research_release_manifest.json`.

## Последующее исследование BTC/ETH и валютных контрактов

Исследовательские варианты находятся отдельно от исполняемой v1. `app/strategy/volium_v2.py` проверяет другую формализацию текущего движения и силу реакции; её численные правила не являются опубликованными настройками автора. Ни выигравший обучающий вариант, ни отдельные прибыльные сделки автоматически не включают торговлю. [Спецификация v2](docs/strategy_v2.md) и [протокол](docs/research_protocol.md) раскрывают гипотезы и порядок выбора.

Для MEXC сохранены 330 дней M5 BTC/ETH и EUR/GBP/JPY, фактический funding и отдельный M1-контроль за последний месяц. Длительная M1-история публичным API не получена. M5-исполнение обозначено как грубая модель. Валютный состав проверяется с повышенными издержками и текущими ограничениями контрактного объёма/шага; исторические спреды и индивидуальные комиссии аккаунта неизвестны. [Проверка инструментов и ликвидности](docs/research_assets.md).

Отдельный набор Binance BTC/ETH содержит два полных года фактических M1 и funding за 2024–2025. Он проверяет правила на другой площадке и не представляет доходность MEXC. [Данные и контроль точности времени](docs/external_data.md). Загрузка публичного архива: `python -m app.external_data`; ключи не используются.

`app.research_suite` сначала регистрирует неизменяемый план с сеткой, рынками, датами, издержками и SHA256, затем выполняет `train`, `validation` и отдельную команду `final`. Train требует положительного результата после издержек и хотя бы 10 закрытых сделок, validation/test — хотя бы 3; открытых позиций при допуске быть не должно. Это разведочные минимумы: менее 30 сделок помечаются малой выборкой. Финальные цены не используются для смены кандидата; если подходящего кандидата нет, финальный участок не рассчитывается. Сохраняются все неудачные варианты и ранее выполненные попытки.

Пример заранее заданного длительного эксперимента другой площадки:

```powershell
.\.venv\Scripts\python.exe -m app.research_suite register --cache .cache/binance_core --out-dir outputs/research_binance --name binance-core-m1-v2 --market crypto_core=BTC_USDT,ETH_USDT --mode intraday --mode scalp --execution-resolution 1m --fold train=2024-01-01T00:00Z/2025-01-01T00:00Z --fold validation=2025-01-01T00:00Z/2025-07-01T00:00Z --fold test=2025-07-01T00:00Z/2026-01-01T00:00Z
.\.venv\Scripts\python.exe -m app.research_suite train --out-dir outputs/research_binance --workers 2
.\.venv\Scripts\python.exe -m app.research_suite validation --out-dir outputs/research_binance --workers 2
.\.venv\Scripts\python.exe -m app.research_suite final --out-dir outputs/research_binance --workers 2
```

Для точного повтора распакуйте `research_mexc_data.zip` в `.cache/research/m5_330d` либо `research_binance_data.zip` в `.cache/binance_core`. Исходники замороженной v2 и контрольные суммы сохраняются отдельно. Повторная регистрация не заменяет существующий план. Итоги новых этапов, пределы выборки и обоснование следующей версии следует читать в отчётах исследования; результат v1 выше сохраняется как контроль.

Для причинных графиков найденного исследовательского входа установите `requirements-research.txt` и используйте `python -m app.research_review`. График содержит только свечи, закрытые к подтверждению, и не используется для выбора по будущей доходности.

Продолжение завершено: всего 635 расчётов сценариев/этапов, плюс два старых общих портфеля отдельно. **Подтверждённого прибыльного MEXC-кандидата нет.** Лучший положительный контроль v3 на MEXC дал +1.28 USDT на двух сделках, что не прошло заранее заданные минимумы. В последней гипотезе v4 все 72 основных рыночных испытания дали ноль сигналов. Итоговые участки всех шести планов не открывались, поскольку train/validation не дали подходящего кандидата; stress final поэтому не рассчитывался. [Полный вывод и пределы проверки](docs/research_results.md), [планы/счётчики/SHA](docs/research_evidence.json).

Исправленная [v3](docs/strategy_context_followup.md) сохраняет целость A на младших свечах и группирует один захват ликвидности со стопом за настоящим краем. [v4](docs/strategy_post_sweep.md) отдельно проверяет закрытое дневное подтверждение после фактического снятия. Ни одна версия не объявляется точной копией ручного решения автора. [Его пример 24 июня 2025](docs/strategy_author_case_audit.md) выявил расхождение численного pre-A тренда; старые [визуальные кадры](docs/video_visual_audit.md) повторно открыть не удалось. Численные фильтры и защищённые настройки сессий не раскрыты источником. В исследовании V2–V4 исполняемая V1 была бумажным контролем. Текущий default V6 paper описан выше; прежние двигатели сохранены.

Новые версии запускаются отдельными командами `python -m app.research_followup` и `python -m app.research_post_sweep`. Их [протокол v3](docs/research_followup_protocol.md) и [протокол v4](docs/research_post_sweep_protocol.md) фиксируют сетки, все прежние попытки, повторное использование данных и независимый выбор площадок. Для v4 оба плана должны быть зарегистрированы до train; обязательны четыре завершённых родительских плана, исходный архив v3 с соседним per-file manifest и `--peer-out-dir`. Планы содержат абсолютные пути исходной машины: при переносе создавайте новый план с прежними датами/данными/параметрами, существующий подписанный JSON не редактируйте.

Текущий `mexc_volium_bot.zip` содержит Python-код, тесты и документы. Неизменённые результаты V1–V4, включая проигравшие и нулевые варианты, находятся в `research_results.zip`; V5 сохранена отдельно в `strategy_v5_results.zip`, V6 — в `strategy_v6_results.zip`. Публичные длительные данные — в двух `research_*_data.zip`, а новый robustness core+top3 — в `research_v5_robustness_data.zip`. Замороженные версии исходников сохранены отдельно как `research_v2_source.zip`, `research_v3_source.zip`, `research_v4_source.zip`, `research_v5_source.zip`. Внешний2021 — `research_v6_external_data.zip`. API-ключи для этих расчётов не используются.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q app
```

Проверки охватывают декларированную численную интерпретацию, отсутствие будущих данных, геометрию 2R, сессии/DST, причинное исполнение, funding, повторные сигналы, перезапуск, подпись MEXC, шаг контракта и неизвестный результат отправки. Они не доказывают совпадение с ручной разметкой автора или заявленный винрейт70%. Публикуемые файлы и API не содержат ключей.

## API

`GET /api/status`, `/api/config`, `/api/setups`, `/api/executions`; `POST /api/setups/{id}/cancel` отменяет только ожидающую входа заявку. Полная схема доступна на `/docs`. Панель привязана к `127.0.0.1`; для удалённого доступа нужны отдельная аутентификация и сетевые настройки.
